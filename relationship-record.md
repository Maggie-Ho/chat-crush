# Relationship record

## Consent and location

Do not save by default. On a first save, ask the user to confirm a user-controlled location, for example `relationships/<chosen-alias>.md`, and list the information that will be stored. Use an alias or initials rather than a full name unless the user specifically prefers otherwise.

If there is no writable workspace, keep a clearly labelled in-conversation summary and say it is not persistent.

## Minimal profile template

```markdown
# Relationship profile: <alias>

## Scope
- Purpose: <user's stated goal>
- Last updated: <date, if known>

## Known context
- Relationship / setting: <only user-provided facts>
- User preferences: <tone, communication goals>

## Timeline
- <date or approximate time>: <observable event>

## Recent patterns
- Reciprocity: <facts, not inferred feelings>
- Boundaries or preferences stated: <exact paraphrase where possible>

## Next respectful step
- <one user-approved action or pause>
```

Record only material, user-provided events: contact or dates, invitations and outcomes, stated preferences and boundaries, and the user's own goals. Do not retain passwords, addresses, private contact details, intimate content, diagnoses, or speculation about the other person's motives.

## Updates and deletion

Before editing, read the existing profile and append or revise only the relevant factual section. Distinguish a reported event from an interpretation. If the user asks to delete a profile, remove the exact agreed file only, then confirm its deletion. Do not retain a hidden copy or reconstruct it later.
